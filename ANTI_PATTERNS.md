# Anti-Patterns

Status: derived AI-generation context. Not canonical. Sources: UX, Design DNA, Material System, Motion Language, Home Screen Philosophy, AI Personality, and Meal Object Model.

## Purpose

Use this file as a drift-prevention reference for Figma Make, Gemini, Galileo, Framer AI, and visual UI generation systems. If a generated screen resembles any pattern below, reject or revise it.

## Forbidden Patterns

### Chatbot UI

No message bubbles, assistant avatars, chat history, typing indicators, or conversational replies. Solodko is operational: input resolves to meal objects.

### Dashboard Density

No dense home dashboard, analytic overview, daily totals as the main screen, stacked widgets, or KPI blocks. The Home Hub is a stage and console, not a data cockpit.

### Fintech Aesthetics

Avoid cold card-deck density, financial charts, neon accents, account-dashboard hierarchy, and high-pressure conversion styling. These signals imply money management, not calm food memory.

### Calorie-Tracker UI

No calorie-first hierarchy, macro rings, nutrient bars, daily quota progress, before/after food judgment, or "remaining today" framing. Solodko counts carbs without turning eating into a score.

### Medical Styling

No hospital white/grey dominance, warning panels, clinical tables, medical icons, red alerts, or patient-portal density. The audience needs relief from clinical burden.

### Gamification

No streaks, points, badges, rewards, celebratory animations, progress-pressure loops, or "great job" copy. Gamification creates failure states and meal anxiety.

### Productivity App Feeling

No checkboxes, task lists, completion dashboards, project-management rows, or habit checklist surfaces. Eating is not a task backlog.

### Robotic AI Visuals

No robot heads, faces, eyes, smiley orb, assistant mascot, neural-network decoration, or sci-fi AI graphics. The AI is invisible, not performed.

### Generic Glassmorphism

Do not apply frosted glass everywhere. Glass is reserved for primary elevated objects: meal cards, active input, and orb. Secondary surfaces use soft solids.

### Aggressive Gradients

No neon sweeps, saturated purple-blue hero gradients, rainbow blobs, or startup-style gradient decoration. Atmosphere should be warm, slow, and restrained.

### Enterprise UI

No dense tables, filter panels, admin settings pages, compact rows with dividers, or high-information dashboards. Solodko should feel premium and personal.

### Toolbar-Like Navigation

No crowded tab bars, 4+ primary tabs, promotional tabs, notification badges, top toolbars packed with icons, or persistent action ribbons. Navigation should stay minimal: Home, Log, Memory.

### FAB-Like Orb Behavior

The orb is not a plus button. It should not use generic FAB shape, icon, color pop, radial menu spectacle, or move around the screen. It is a bottom-centered system-state object and input anchor.

## Global Rejection Rule

Reject any generated UI that makes Solodko feel like a chatbot, tracker, medical app, fintech app, productivity app, gamified wellness app, or generic AI demo. The correct signal is warm premium calm plus structured operational clarity.
